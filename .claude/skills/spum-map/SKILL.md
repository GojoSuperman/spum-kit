# SPUM 맵 만들기

AI 가 그린 조감도 한 장을 SPUM Studio 맵으로 만든다.
타일을 반복해 까는 방식과 달리, **씬 전체를 한 장으로 그려 32×32 격자로 잘라
1024칸을 각각 고유 타일로** 등록한다. 그래서 완성된 일러스트가 그대로 맵이 된다.

## 0. 먼저 묻는다 — 절대 건너뛰지 말 것

**바로 프롬프트를 쓰지 않는다.** 회당 약 250쌤이 들고, 그림이 나온 뒤에 방향이
틀렸다는 걸 알면 그 비용이 그대로 날아간다.

`AskUserQuestion` 으로 확인한다. **이미 사용자가 말한 항목은 다시 묻지 않는다.**

| 물을 것 | 왜 중요한가 |
|---|---|
| **구역 구성** | 프롬프트의 뼈대. "무엇이 어디에" 가 결과를 가장 크게 좌우한다 (바는 우상, 계단은 우하 …). 3~6개 구역이 적당하다 |
| **양식 · 시대** | 중세 / 현대 / SF / 판타지 + 구체 스타일. 같은 "주점" 도 완전히 달라진다 |
| **분위기 · 조명** | 낮/밤, 따뜻함/차가움. **밝은 씬일수록 마스크 정확도가 높다** (실측) |
| **녹화 여부** | 작업 과정을 webm 으로 남길지. 남기면 `--record` 를 붙인다 |

방식(씬 vs 타일)이 불분명하면 이것도 묻는다:
- **씬** — 고품질 일러스트, 약 250쌤, 그 맵 전용, 저장소 ~500KB
- **타일** — 비용 0, 여러 맵에 재사용, 품질은 낮음 (이 스킬이 아니라 `make-map.mjs` 를 쓴다)

답을 받으면 **프롬프트 초안을 보여주고** 실행한다. 과금 직전이기 때문이다.

## 1. 프롬프트 쓰기

`references/프롬프트 예시.md` 에 검증된 것 두 개가 있다. 그 골격을 따른다.

```
Top-down orthographic <장소>, one continuous scene, game map art.
<구역1> at <위치>, <구역2> at <위치>, …          ← 배치를 명시한다
<바닥 재질>, <벽 재질>, <소품>.
No text, no people, no UI. Square, aligned to a 32x32 grid.
```

지켜야 할 것:

- **520자 이하.** 507자에서 `504 Gateway Timeout`, 446자에서 성공했다(실측).
  넘으면 구역 배치는 남기고 수식어부터 줄인다.
- **`No text, no people, no UI`** 를 반드시 넣는다. 없으면 라벨과 사람이 들어간다.
- **`aligned to a 32x32 grid`** 로 격자 정렬을 요구한다.
- 사람·캐릭터는 넣지 않는다. 캐스트는 Studio 에서 따로 배치한다.

## 2. 실행

```bash
npm run scene-map -- --name "<맵 이름>" --prompt-file <프롬프트 파일> --headed --quality medium [--record]
```

창 하나가 뜨고 여섯 단계가 이어진다:

```
① 씬 조감도 생성 (AI)          ④ 통행 판정 · 고립 구역 잇기
② 참조본 512² 축소             ⑤ Studio 주입
③ 통행 마스크 생성 (img2img)   ⑥ 새로고침 · 확인 스크린샷
```

- `--headed` 를 빼면 창 없이 돌지만, 사용자가 지켜볼 수 없다. **기본으로 붙인다.**
- `--quality medium` 을 기본으로 붙인다. high 는 생성이 60~70초로 길어져 앞단 nginx 타임아웃(504)에
  걸린다 — 실측으로 같은 프롬프트가 high 에서 두 번 연속 504(249쌤 증발), medium 에서 36초에 통과했다.
  화질을 최대로 뽑아야 할 때만 `--quality high` 로 올린다.
- `--record` 를 붙이면 전 과정이 `out/videos/*.webm` 으로 남는다 (창을 닫아야 파일이 떨어진다).
- `--dry-run` 은 그림만 만들고 주입하지 않는다.

## 3. 확인 — 눈으로 본다

주입 전에 **마스크 오버레이를 반드시 확인**한다. `out/scene-walkmask.png` 에
초록(통행)/빨강(막힘)이 칠해져 나온다. 가구·벽이 빨강이고 바닥이 초록이면 정상이다.

주입 뒤에는 `out/scene-final-*.png` 스크린샷을 열어 실제로 렌더됐는지 본다.

**야외 맵이면 물을 특히 본다.** 마스크 프롬프트에 물이 빠져 있어서 수로 88칸 중 73칸이
통행으로 잡힌 적이 있다 (2026-08-20, 판타지 시장 광장). 지금은 프롬프트에
`water, rivers, canals, ponds, fountains, pits` 가 들어가 있지만, 결과는 매번 확인한다.

고립 구역은 `--connect` 가 자동으로 잇는다 (기본 켜짐). 몇 칸을 뚫었는지 로그에 나오며,
어디를 뚫었는지 궁금하면 좌표를 뽑아 이미지로 표시해 보여준다.

## 4. 막혔을 때

| 증상 | 원인과 대응 |
|---|---|
| `504 Gateway Timeout` | **`--quality medium` 으로 낮춰 재시도**(가장 잘 듣는다). 그래도 나면 프롬프트를 450자대로 줄인다. 앞단 nginx 가 늘어진 생성을 끊는 것이라 **과금은 된다** — 로그의 `[api] 504 … N초` 로 몇 초에서 끊겼는지 확인할 수 있다 |
| `413 Payload Too Large` | 참조 이미지가 크다. 한도는 **base64 기준 1MiB ≈ 파일 780KB** — 512² PNG 도 디테일이 많으면 넘는다 (실측: 773KB 통과, 815KB 거부, 2026-08-21 산동네 마을). 스크립트가 512² 축소 + 한도 초과 시 JPEG 재인코딩까지 자동 처리한다. 마스크 단계에서 죽었으면 `--scene <씬 PNG>` 로 씬 생성 과금 없이 재개한다 |
| `QuotaExceededError` | localStorage 한도(약 5MB). `--jpeg 60` 으로 더 압축하거나, 큰 항목을 지운다. **무엇을 지울지 사용자에게 먼저 묻는다** |
| 프로필 점유 오류 | `npm run studio-open` 창이 떠 있다. 닫고 다시 실행 |
| 세션 만료 | **세션은 로그인 후 약 30분에 서버가 끊는다** (2026-08-21 계측: 15분에 쿠키 회전 1회 → 30분에 종료, 백업 쿠키도 서버에서 거부). 자동 갱신은 그 안에서만 된다. 따라서 **작업은 로그인 직후 몰아서** 하고, 프롬프트·재생성 등 브라우저 없는 준비를 먼저 끝낸 뒤 `npm run studio-login` → 주입·생성 순으로 돌린다. 죽었으면 재로그인뿐이다 |
| 마스크가 부정확 | 밝은 씬일수록 잘 나온다. 조명을 밝게 바꿔 씬부터 다시 뽑는 게 빠르다 |

## 5. 전제 조건

- `npm i && npx playwright install chromium` + 시스템 라이브러리(`install-deps`)
- `npm run studio-login` 으로 **한 번 로그인** (SSO 는 이메일 매직링크라 사람이 해야 한다).
  로그인 프로필은 홈 공용(`~/.spum-studio`)이라 **프로젝트마다 다시 하지 않아도 된다.**
- 세션은 로그인 후 약 30분에 서버가 끊는다 — 작업은 로그인 직후 몰아서 (4절)
- 다른 브라우저나 다른 프로젝트에서 Studio 를 만졌다면 시작 전에 **`npm run studio-pull`** —
  동기화가 append-only 라 낡은 로컬로 열면 그게 최신 리비전이 된다
  (`docs/Studio 를 두 곳에서 쓰기.md`)

새 프로젝트에 이 킷을 깔려면:

```bash
git clone --depth 1 https://github.com/GojoSuperman/spum-kit.git /tmp/spum-kit \
  && bash /tmp/spum-kit/install.sh
```

세부 실측과 함정은 원본 저장소의 `docs/Studio와 Claude Code 역할 분담.md` 8~10절에 있다.
